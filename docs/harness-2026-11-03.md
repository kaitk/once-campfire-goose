# Shared harness run on an M1 Pro (November 3, 2026)

Goose against the Rust implementation in
[basecamp/once-campfire-verification](https://github.com/basecamp/once-campfire-verification),
the shared harness, with Goose added as an optional `goose` app, after the Rails parity work
listed in [Rails parity, browser coverage and live delivery](browser-parity.md). Every response
was checked against its route contract and every acknowledged post was audited against the
database; the harness stops a run at the first invalid response or failed audit. The harness
wrote the JSON files in [`harness-2026-11-03/`](harness-2026-11-03/); its per-request `raw/`
output is left out. The [November 2 run](harness-2026-11-02.md) measured `55ca74c`, before that
work.

| Input | Revision |
|---|---|

| Rust application | `6dae2fd3c1a2dce61ca11beb731bcce2b42b67ad`, published image `ghcr.io/basecamp/once-campfire-rust@sha256:98ba156f688c3fe856afd71655f613a6620bc03754f456ed2ef08fb2e5527e6e` (its `main` tag) |
| Harness | `971063a`: upstream `ec02deb` and two commits that add the `goose` app |
| Seed | the harness's fixture from Rails `90b3300`, SHA-256 `421a36cf…` |

Rust's `main` image is the newest it publishes. Its `latest` tag points to an older build
(`24c8597`, September 29), which orders search results by `created_at`; the harness's contract
expects the order of Rails since [#304](https://github.com/basecamp/once-campfire/pull/304), by
message id, which Rust's `main`, the Jai port and now Goose follow.

## Host

Apple M1 Pro (10 cores, 32 GB) with Docker Desktop 29.9.2 (a linuxkit VM with 10 CPUs and 8 GB),
as on November 2. `bin/benchmark` ran in a Linux container with the Docker socket mounted, as
uid 1000, with the apps on CPUs 0–3 and the load generator on 4–9, and the harness checkout, the
seed and the runtime databases on the VM's own disk (`/var/lib/cfbench`).

## Results

`bin/benchmark --apps rust,goose`: 3 alternating rounds, 16 clients, 8 seconds per route.
Requests/sec, median of 3 rounds (range):

| Route | **Goose** | Rust | Goose vs Rust |
|---|---:|---:|---:|
| Post a message | **6,060** (6,059–6,156) | 2,744 (2,712–2,765) | **2.21×** |
| Room page | **107,552** (105,773–108,555) | 22,458 (22,398–22,837) | **4.79×** |
| Messages page | **115,203** (111,295–123,317) | 21,375 (21,323–21,424) | **5.39×** |
| Sidebar | **116,001** (115,465–119,840) | 24,807 (24,726–25,064) | **4.68×** |
| Search | **122,647** (112,567–136,607) | 24,784 (24,693–24,801) | **4.95×** |

Valid responses: 18,368,079 for Goose and 6,884,850 for Rust, with no invalid responses and no
errors. Acknowledged posts, all verified: 182,638 for Goose and 80,854 for Rust.

`bin/benchmark --apps rust,goose --mixed-write-rate 10` adds one writer that posts 10 messages/sec
to the room while the pages are read:

| Route | **Goose** | Rust | Goose vs Rust |
|---|---:|---:|---:|
| Room page | **100,425** (99,969–101,493) | 19,977 (19,821–20,093) | **5.03×** |
| Messages page | **106,384** (105,344–109,171) | 19,293 (18,921–20,123) | **5.51×** |
| Sidebar | **120,346** (115,358–129,819) | 24,456 (24,240–26,040) | **4.92×** |
| Search | **116,951** (110,982–127,712) | 23,405 (23,404–23,842) | **5.00×** |

Valid responses: 10,752,896 for Goose and 2,109,392 for Rust, with no invalid ones; each
round's 400 writes were verified.

As [the Jai README](https://github.com/lucasmeijer/once-campfire-jai#measurements) says, the page
routes are benchmaxxed: 16 connections share one session and repeat one URL, so a cache of
finished pages answers nearly every request. The posting row is the one that reflects
production.

## Against November 2

Both apps measured lower than on November 2: Rust by 4–22% and Goose by 6–35%, depending on the
route. To tell the host's
state from the parity work's cost, the November 2 build (published as
`ghcr.io/kaitk/once-campfire-goose:sha-2a745ef`, whose application code is `55ca74c`) and this
one ran alternately in the same session, `bin/benchmark --apps goose --rounds 2` four times. The
files are in [`harness-2026-11-03/ab/`](harness-2026-11-03/ab/); their recorded source revision
is the checkout's, `16e1bc9`, for both images. Medians, requests/sec:

| Route | `55ca74c`, run 1 | `16e1bc9`, run 1 | `55ca74c`, run 2 | `16e1bc9`, run 2 |
|---|---:|---:|---:|---:|
| Room page | 115,867 | 107,601 | 109,048 | 106,205 |
| Messages page | 111,801 | 113,407 | 112,277 | 117,005 |
| Sidebar | 120,343 | 114,555 | 116,491 | 113,042 |
| Search | 117,817 | 113,235 | 116,496 | 115,314 |
| Post a message | 6,392 | 6,440 | 6,178 | 6,080 |

The session, not the code, accounts for most of the drop. Between the two builds, the room page
and the sidebar are 4–5% lower, search 2% lower and the messages page 3% higher, within about the
spread of repeated runs; posting is unchanged. The parity work adds about 280 bytes of headers to
every page (an ETag, Cache-Control and Rails' default headers), which the page cache computes once
per stored page.

## Reproducing on a Mac

As in the [November 2 report](harness-2026-11-02.md#reproducing-on-a-mac), with
`-e RUST_IMAGE=ghcr.io/basecamp/once-campfire-rust@sha256:98ba156f688c3fe856afd71655f613a6620bc03754f456ed2ef08fb2e5527e6e`
and `GOOSE_IMAGE=ghcr.io/kaitk/once-campfire-goose:sha-<revision>` (or a local build) passed to
the harness's container.
