# Shared harness run on an M1 Pro (November 2, 2026)

Goose against the Rust implementation in
[basecamp/once-campfire-verification](https://github.com/basecamp/once-campfire-verification),
the shared harness, with Goose added as an optional `goose` app. Every response was checked
against its route contract and every acknowledged post was audited against the database; the
harness stops a run at the first invalid response or failed audit. The harness wrote the JSON
files in [`harness-2026-11-02/`](harness-2026-11-02/); its per-request `raw/` output is left out.

## Host

Apple M1 Pro (10 cores, 32 GB) with Docker Desktop 29.9.2 (a linuxkit VM with 10 CPUs and 8 GB).
`bin/benchmark` ran in a Linux container with the Docker socket mounted, as uid 1000. The apps were
on CPUs 0–3 and the load generator on 4–9: six cores for the load generator, where the harness's
defaults give it four.

The harness checkout, the seed and the runtime databases were on the VM's own disk
(`/var/lib/cfbench`), not on the macOS file share. On the share, SQLite writes are about ten
times slower. A first run from the share measured 598 Rust and 723 Goose posts/sec, and its
post numbers are discarded. Its page medians were within 4% of the run below for Goose, and
within 15% for Rust.

The absolute numbers are lower than on the Linux hosts in the harness README, and they don't
compare with this repository's Ryzen sessions.

## Results

`bin/benchmark --apps rust,goose`: 3 alternating rounds, 16 clients, 8 seconds per route.
Requests/sec, median of 3 rounds (range):

| Route | **Goose** | Rust | Goose vs Rust |
|---|---:|---:|---:|
| Post a message | **6,459** (6,455–7,539) | 3,422 (2,818–3,429) | **1.89×** |
| Room page | **133,491** (130,480–157,134) | 23,594 (23,414–27,317) | **5.66×** |
| Messages page | **138,485** (136,631–169,393) | 22,336 (21,325–25,695) | **6.20×** |
| Sidebar | **144,138** (141,068–168,813) | 27,322 (24,835–30,448) | **5.28×** |
| Search | **140,442** (137,063–163,964) | 29,020 (24,907–30,677) | **4.84×** |

Valid responses: 22,895,373 for Goose and 7,605,589 for Rust, with no invalid responses and no
errors. Acknowledged posts, all verified: 204,693 for Goose and 94,766 for Rust. Both apps ran
faster in the third round.

`bin/benchmark --apps rust,goose --mixed-write-rate 10` adds one writer that posts 10 messages/sec
to the room while the pages are read:

| Route | **Goose** | Rust | Goose vs Rust |
|---|---:|---:|---:|
| Room page | **153,902** (151,579–159,170) | 25,466 (24,947–25,567) | **6.04×** |
| Messages page | **162,586** (161,202–171,040) | 24,020 (23,154–24,149) | **6.77×** |
| Sidebar | **167,826** (166,942–168,810) | 30,421 (30,278–30,431) | **5.52×** |
| Search | **170,576** (165,981–175,501) | 29,495 (29,153–29,498) | **5.78×** |

Valid responses: 15,802,325 for Goose and 2,612,914 for Rust, with no invalid ones; each
round's 400 writes were verified. Despite the writer, this run's page medians were 15–22% higher
for Goose and 2–11% higher for Rust than the plain run's, so differences of that size between
sessions are noise on this host.

As [the Jai README](https://github.com/lucasmeijer/once-campfire-jai#measurements) says, the page
routes are benchmaxxed: 16 connections share one session and repeat one URL, so a cache of
finished pages answers nearly every request. Ten writes a second hardly change that. The posting
row is the one that reflects production.

## Reproducing on a Mac

```sh
B=/path/to/workspace   # verification/, once-campfire-rust/ and once-campfire-goose/ side by side
V=/var/lib/cfbench     # a path inside Docker Desktop's VM
docker run --rm -v $B:/src:ro -v $V:$V alpine sh -c \
  "cp -a /src/verification /src/once-campfire-rust /src/once-campfire-goose $V/ && chown -R 1000:1000 $V"
docker run --rm --network host -u 1000:1000 --group-add 0 -e HOME=/tmp -e LANG=C.UTF-8 \
  -e GIT_CONFIG_COUNT=1 -e GIT_CONFIG_KEY_0=safe.directory -e GIT_CONFIG_VALUE_0='*' \
  -v /var/run/docker.sock:/var/run/docker.sock -v $V:$V -v $B/results:/out -w $V/verification \
  campfire-runner ruby bin/benchmark --apps rust,goose --workspace $V \
  --cpus 0-3 --client-cpus 4-9 --output /out/<new directory>
```

`campfire-runner` holds what the harness needs on Linux; build the load generator with it
(`cargo build --release --locked --manifest-path loadgen/Cargo.toml`) before the copy:

```dockerfile
FROM rust:1.98.1-bookworm
RUN apt-get update && apt-get install -y --no-install-recommends ruby sqlite3 ffmpeg git util-linux python3 \
    && rm -rf /var/lib/apt/lists/*
COPY --from=docker:27-cli /usr/local/bin/docker /usr/local/bin/docker
COPY --from=node:22.18-bookworm /usr/local/bin/node /usr/local/bin/node
```

Docker Desktop's host network can't be reached from macOS itself, so everything that talks to
the apps runs inside the VM.
